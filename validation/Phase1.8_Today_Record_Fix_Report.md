## 1. 问题描述（用户报告）

在**非计划日**手动启动训练并选择「结束并保存为未完成」后：

- 训练已正确写入 `workoutHistory`（训练历史可见 ✅）
- 但 **Today 首页没有显示当天的这次训练** ❌

要求（本轮仅修复此一项，不动视觉结构、不加新页面）：

1. Today 同日读取**所有** workout session（计划训练、手动额外训练、完整训练、提前结束训练），不因 session 不是当天原计划就隐藏；
2. 原定训练卡继续显示，**不要错误标记为已完成**；
3. 原定训练卡下新增「今日训练记录」区；记录显示：`已额外训练 · 提前结束 / 胸 / 肩 / 肱三头肌 / 1/4 个动作 · 1/14 组 · 完成率 7% · 容量 560kg`，**点击进入对应训练历史详情**（`/training/history/:id`）；
4. 完整完成的额外训练用「已额外完成」；
5. 当天多次训练**全部展示、按时间倒序**；**刷新后不消失**。

---

## 2. 根因

`src/pages/Today.tsx` 中，`extraToday = state.workoutHistory.filter(w => w.date === today)` 虽然已经能取到当天全部 session，但**渲染代码把这部分数据绑定在「今日原计划为休息日」的分支内**（`todayPlan.active === false` 的分支）。当今天为**计划日**（用户场景：周四原定腿部）时，页面走 `todayPlan.active ?` 的「开始训练」卡分支——该分支完全丢弃了 `extraToday` 数据。

→ 于是：周四（计划日）手动完成了一段周一（额外）训练并保存后，Today 仍只显示周四原定腿部卡，没有任何当天训练记录。

**线上旧版复现证据**：对生产站点（修复前 bundle）执行同一验收流程，`v18_4_today_MISSING_RECORD_bug.png` 与 training 前的初始 Today 截图**字节完全相同（280,703 B）**——即训练结束后 Today 页面毫无变化，记录被隐藏。

---

## 3. 修复方案（`src/pages/Today.tsx` 改动）

1. 新增当日聚合数据层（不再只取「最近一场」，取当天全部并按时间倒序）：

   ```ts
   const todayIdx = (new Date().getDay() + 6) % 7
   // 当天全部已保存的训练会话（含计划训练、手动额外训练、完整训练、提前结束训练），
   // 不因 session 不属于当天原计划而隐藏。
   // workoutHistory 按保存先后追加，倒序即「完成时间新的在前」。
   const todaySessions = [...state.workoutHistory].filter((w) => w.date === today).reverse()
   ```

2. 计划日「开始训练」原定卡**保持原样**（仍显示"开始训练"，不因额外训练而标记已完成），仅在其下方新增「今日训练记录」区（用 Fragment `<>...</>` 包裹两个兄弟节点）：

   - 逐条渲染 `todaySessions`：整卡 `<Link to={"/training/history/"+w.id}>`，可点击进详情；
   - 状态文案按 「是否当天原计划日 + 是否 completed」区分：
     - 额外（`w.dayIndex !== todayIdx`）：partial → **已额外训练 · 提前结束**；completed → **已额外完成**；
     - 计划日当天的 session：partial → 今日计划训练 · 提前结束；completed → 今日计划训练 · 已完成；
   - 肌群徽标：从已完成的动作的 `primaryMuscle + secondaryMuscles` 经 `muscleCn` 取（胸 / 肩 / 肱三头肌）；
   - 指标行：`完成动作/计划动作 个动作 · 完成组数/计划组数 组 · 完成率 X% · 容量 Y kg`（`generateWorkoutSummary` + `sessionVolume` + `fmtVol`）。

3. 休息日分支逻辑不动（旧逻辑已正确显示额外训练，维持现状避免非本次范围改动）。

> 说明：原定训练卡「不误标已完成」语义 = 计划日顶部卡始终是"开始训练"（即使今天额外/计划训练已保存），完成的 session 只体现在下方「今日训练记录」区。
